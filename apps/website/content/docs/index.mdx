Nooks is one binary. It serves the API and the app from the same process and keeps
everything in one SQLite file you can copy — no separate database to stand up, no queue,
and no mail server.

These pages are written for whoever runs the instance. Nothing here assumes a cluster.

## How these pages are organised

**Install**, **Configure** and **Reverse proxy** get an instance up and pointed at the
right database and domain. **Back up** and **Upgrade** are the two things you will do
again, so they are written to be re-read rather than read once.

**Using the API** and the **reference** are for anybody automating against an instance —
a script, a shortcut, or an assistant over MCP. The reference is generated from the same
definitions the server is built from, so it cannot describe an endpoint that is not
there, and a check in CI refuses an endpoint that ships without a route.

## If something is wrong

Live updates arriving nowhere is almost always a reverse proxy buffering the event
stream — [the proxy page](/docs/reverse-proxy) has the headers that fix it. Anything
else is worth [raising as an issue](https://github.com/hoshomoh/nooks/issues): a
self-hosted app that fails quietly on somebody's machine is a bug report nobody can
write without help.
